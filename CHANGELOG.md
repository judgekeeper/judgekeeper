# Changelog

## 1.1.0 (2026-11-03)
- Bring labels you already have: `judgekeeper --labels <file>` or, for labels already in your results, `judgekeeper --labels`. Mark more on the page if needed.
- The result page links back to the marking page, and says how to mark more after closing it (`judgekeeper mark`). When every answer is marked, the table has no "Between" column. Two range ends that look the same get a second decimal, or "almost exact". A number or a range end is never shown as 100% or 0% unless it is exactly that; a very narrow range is shown with decimals. Opening the result page before there is a result writes nothing. Its "What next" says the same as the terminal. "Its reason" shows only when some answers have a reason, and a saved reason closes its box. The marking page's status always agrees with the result page.
- "Good enough" and "needs work" now need stronger evidence, so a lucky streak can't decide them. The first numbers wait for 20 marks on answers your LLM-as-a-judge passed and 20 on answers it failed. A good LLM-as-a-judge needs more marks than before to hear "good enough".
- After your first 10 marks, about 1 in 20 marked answers comes back once, so you can see how often your own marks change.
- `fix` and `check` count each mark for its share of your answers, so "Safe to try" is said by mistake less often.
- When you mark every answer, the numbers show no range, and nothing asks you to mark more.
- A mark can always be changed: when every answer is marked, the result page links to the marking page, and `judgekeeper mark` opens it.
- When the only answers left to mark are ones you skipped, judgekeeper says to look at them again or run your eval on more questions, not to mark more.
- Labels: a labels file is read row by row, with no row cap. An open marking page sees imported marks and skips those answers. An import that adds nothing says why. `--label-map WORD=error` skips rows with no decision. Labels match answers whose accents are written the other way. Scores edited in Inspect AI are not used: Inspect keeps a label only when a person changes a score, so they would be mostly disagreements. A label written `1.0` or `0.0` reads as 1 or 0. A labels file with two columns for the same thing stops and asks you to keep one. A labels file takes the same column names as a results file (`response`, `question`, ...), and when it has no answer column it names the columns it found. A CSV whose notes have line breaks is read, not refused. A row with more cells than the header stops and names the line. A model column is read the same way in CSV and JSONL files. After `check`, labels for answers your LLM-as-a-judge didn't grade Pass or Fail are sorted as before. `--new --labels FILE` keeps `--labels FILE` in the commands it prints.
- Paths: what judgekeeper prints names a path from where you run it, or as `~/...`; on Windows, a command that can't run any other way gives the whole path. Lines that name a found file use the same form. A path is never split across two lines. No line shows a user name: a folder inside another user's home is shortened (`/…/project/`). Files in `.judgekeeper/` name paths from the project folder or as `~/...`, never with your user name; older files still read.
- From `/`, a drive, or the folder above your home, judgekeeper no longer searches the folders below. It asks you to go to your project folder. Find skips devices, pipes and folders it can't open.
- Commands: Next lines name a command that runs as shown, also when `judgekeeper` is not on the PATH (`venv/bin/judgekeeper`, or `python3 -P -m judgekeeper`), and on Windows in both cmd and PowerShell. Commands name plain `judgekeeper` only when that is the same program you ran; with another judgekeeper on the PATH they name yours. A line that says to run a command in your project folder, or sends you to another folder, names the program and the folder as they are from there. On a project with scores, every printed command keeps the pass mark in use, also after `--stop`. report.html and the files in `.judgekeeper/` name the program plainly, and report.html says when you started judgekeeper another way. Stop lines name the program as you started it.
- Folders: a folder with a project file (pyproject.toml, package.json, .git, ...) keeps its own marks and never reads the project above it. New results in a folder of their own get their own `.judgekeeper/`. A project folder given from another folder is read as the project. Results in the same folder as results a project's marks are for use those marks, from whichever folder you run judgekeeper. `--stop` also closes a page opened from the folder right below.
- Marking page: a key pressed just as a new answer shows, or as the welcome box closes, marks nothing. Long file names and commands wrap. When most marks took under a second, the pages say so. A mark the page can't save says how to open it again. The welcome box says that an answer you marked can come back once, and there is no welcome box once every answer is marked. For your own results file, the page names your LLM-as-a-judge the way the terminal does. Z after changing a mark puts back the earlier mark. The footer names the project folder. A page left open closes when `check` takes on a new LLM-as-a-judge.
- If `.judgekeeper/marks.jsonl` ends in a cut line, the next mark goes on a line of its own and is kept.
- An LLM-as-a-judge that gave every answer one grade gets its result at the first mark the other way.
- `fix` says which marks it used and how many are kept aside, says to keep the old rule when the marks can't settle it, and names only the new results file in its next step. "Tell judgekeeper why you disagree" counts only disagreements with no reason yet. It never asks for more marks than there are answers left. It never suggests a pass mark that `check` would call worse, or one a check already found worse. `fix --port` or `--no-browser` says `fix` opens no page. mistakes.md names a typed reason by its words, keeps the rule you marked with, and calls a word common only when it is.
- promptfoo: regrade.yaml keeps the grader's settings (temperature, max_tokens, ...), but never a field that may hold a key. It holds each answer exactly as marked. After "Safe to try", `fix` says to copy the new rule from `.judgekeeper/fix/regrade.yaml` into your promptfoo config.
- When the numbers include marks you looked at to write the new rule, the result page, report.html and the terminal say so under the verdict.
- `check --pass-if RULE` re-checks the pass mark `fix` suggests on your marks; once taken on, later runs read with it.
- `check`: its first line starts "Compared with before:" and names the side that got worse. The worst end of a drop range is rounded up. When `check` changes your result, it says the new one, and if that is too early to tell, says to mark more. Its next step names a new results file, never the same one again. For a file with only some of your marked answers, it says to grade every marked answer again. "Your eval wrote new answers" is said only when it did. With results in two folders, it names a command for each. After a Worse or Not sure check, or a check of a results file outside your project, the next runs name the right LLM-as-a-judge and the right next step. A missing file is named with its folder. A plain `check` reads the file your last check read, as a plain `judgekeeper` does, unless your eval wrote newer results.
- After `check` takes on a new LLM-as-a-judge that graded only some of your answers, marks on the other answers wait: kept, never counted with an older grade, and counted once `check` brings the new grades, each with its own reason, score and fingerprint. The terminal and every page say how many wait and what to do, and nothing asks you to mark answers whose marks could only wait.
- A plain `judgekeeper` that reads a newer results file than last time says which one. "Your answers were graded again" is said only when the grades changed.
- A new `--pass-if` or LLM-as-a-judge given before any mark reads the results again at once. Without a terminal to ask in, the pass mark question names the pass mark in use.
- history.jsonl keeps each result's verdict.
- Ctrl-C always stops with "Stopped." and exit code 130, with nothing more printed, also while judgekeeper starts or an Inspect AI log is read.
- Large runs are faster: marks and answers are read once per run.
- `record()`, `jk_record.py` and `jk_record.ts` name their records `LLM-as-a-judge` by default; older records still read.
- Docs: the README and the start page say more: `uvx` before each command, the MLflow and Inspect AI extras, the columns a labels file needs, `--no-browser` for coding agents, and that a faithfulness check needs the documents open while you mark. The reference says what 1.1.0 changed: marks that wait, starting from `/`, labels file rules, the promptfoo re-grade file, and `check --pass-if`.

## 1.0.0 (2026-10-30)

The 5 steps: Find. Mark. Measure. Fix. Re-check. In your project folder, in its virtual environment, run `pip install judgekeeper`, then `judgekeeper`; or run `uvx judgekeeper`, which needs no virtual environment.

- `judgekeeper` finds your eval results and their LLM-as-a-judge: promptfoo, DeepEval, Inspect AI, MLflow, a CSV, TSV or JSONL file, or `judgekeeper.record()`.
- You mark answers Pass or Fail in your browser, with the grade hidden. The page accepts marks only from itself, so other websites can't send marks. A program already running on your computer could, just as it can edit your files.
- Then see how often your LLM-as-a-judge agrees with you: TPR and TNR with ranges, and kappa.
- `judgekeeper mark` marks more answers.
- `judgekeeper fix` shows where your LLM-as-a-judge goes wrong and keeps half your marks aside. Grade the marked answers again with your new rule in your eval tool, then `judgekeeper fix <new results file>` tests it on the marks kept aside.
- `judgekeeper check` re-checks it on your marks, from your new results, when something changes: its model, rule, grading prompt, pass mark or temperature, your eval tool's version, and more (the reference lists them all).
- `fix` and `check` find the answers you marked by their text and question. An answer kept aside that a new rule leaves ungraded counts as its mistake.
- judgekeeper only reads files. It never runs your eval tool, makes no AI call and needs no API key.
- It hides keys in what it prints and writes: the key variables in your shell, your project's `.env` and `.env.*` files and promptfoo's `env:` block, and anything shaped like a key.
- Very large Inspect AI logs and MLflow stores are refused with the limit named; the reference lists the limits.
- Reading results: a table with a `score` column and no verdict column is read with `--pass-if`, or judgekeeper asks for a pass mark (exit 3), and the website's browser check says the same. A promptfoo assertion's `threshold` is its pass mark. In a file of your own format, the model field inside the judge object (`judge.grader`, ...) is offered as the model and written into every judgment's fingerprint, and a `response_time` column is not a second answer. A folder with results in two or more folders below it stops (exit 3) and names them. Long files no longer take time that grows with the square of their size. A score table reads answers that run over many lines, and a quote that never closes, or closes only on a later row, stops with its line named, in the tool and the browser check. In the browser check, plain 1 and 0 scores count no Pass or Fail until a pass mark is given.
- `fix` and `check`: a `fix/split.json` changed by hand stops `fix` (exit 2, Next: `fix --new`). `check` on the results your marks were made from says "back to the one you marked with" every time, not "Worse" from the second run on. A DeepEval GEval's rule leaves out the steps its model wrote for each answer, so a plain re-run no longer says "rule changed". A model given later with `--judge-model` is written into the marks and the history too, and a new results file with its own model column is read (`check` names a model change). "Worse" next to a group that rose says which group dropped. With a wrong MLflow scorer name, `fix` and `check` give the same next step. The README, the reference and SECURITY.md say what the code does.
- Marking page and exits: `--wait` keeps the page open until Ctrl-C (exit 130) and leaves no lock; a second run opens no new tab and says the page is already running; a plain run reuses the `--label-map` kept with your marks; keys pressed while a mark is saved act once it is saved; a save with no answer after 10 seconds says it wasn't saved; only `http://127.0.0.1:<port>` may send marks. A file judgekeeper guessed and can't read exits 2, and Ctrl-C, `--debug` and `--version` keep their exit codes when the output can't be printed.
- Removed since 0.1.3: every 0.1 command, the built-in runners that called an AI, the pytest plugin, the GitHub Action and the agent skill.
- The license is now Apache-2.0 (was MIT).
