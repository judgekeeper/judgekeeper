New here? Start with the Guide. This page is for API keys. Checking your judge with judgekeeper start needs none: you need a key only when you ask your judge again (your own eval tool uses it, and judgekeeper only checks its name).

Setup and API keys

A key never goes into a file, a command or a chat. The steps below keep it in an environment variable on your laptop.

Two words first

  • An API key is a secret string, like a password, that lets a program use your account with a model provider such as Anthropic or OpenAI. Anyone who has it can spend your money.
  • An environment variable is a named setting that your terminal or CI system hands to every program it starts. judgekeeper reads keys only from environment variables, so a key never has to be typed into a command or saved in a file.

On your laptop

  1. Create a key just for judgekeeper

    In your provider's console, make a new key and give it a low spending limit. If it ever leaks, little can be spent and you can delete it without breaking anything else.

  2. Save the key where your terminal finds it

    Pick your computer. Linux follows the Mac tab.

    Your shell profile is a file your terminal reads when it starts: ~/.zshrc on a Mac, usually ~/.bashrc on Linux. Open it in a text editor and add one line, with your key in place of the dots:

    export ANTHROPIC_API_KEY=...

    For OpenAI the name is OPENAI_API_KEY. This file lives in your home folder, outside any project, so it never ends up in a repository.

    The profile is read when a terminal starts, so open a new terminal. Then check. This prints set if the key is there, without showing the key:

    echo ${ANTHROPIC_API_KEY:+set}

    Open PowerShell and run this line as it is. It asks for the key: paste it and press Enter.

    [Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", (Read-Host "Paste your key"), "User")

    Windows saves the key for your user account, outside any project, so it never ends up in a repository. You type the key in answer to the question, so the command itself, which PowerShell keeps in its history, does not contain it. The key shows on screen while you paste it: run Clear-Host afterwards if someone can see your screen. For OpenAI the name is OPENAI_API_KEY.

    The saved key reaches only windows opened after this, so open a new PowerShell window. Then check. This prints set if the key is there, without showing the key:

    if ($Env:ANTHROPIC_API_KEY) { "set" }

    To set the key for the window you are in and nothing else, use this line. It is gone when you close the window:

    $Env:ANTHROPIC_API_KEY = Read-Host "Paste your key"

    You can also save it without a command: open the System Control Panel, then System, Advanced system settings, the Advanced tab and Environment Variables, and add ANTHROPIC_API_KEY under the variables for your user. In the other examples on this page, replace a line such as export NAME=... with $Env:NAME = Read-Host "Paste your key".

Where a key must never go

  • Files in your repository, including config files and .env files that get committed. Git keeps history: a key committed once stays findable.
  • Command-line flags. Commands are saved in your shell history and visible to other programs. judgekeeper has no flag that takes a key.
  • Prompts, for the judge or for an AI assistant.
  • Chat messages, issues and screenshots.

If a key leaks, delete it in your provider's console straight away and make a new one.

Good habits

  • Use a dedicated key for judgekeeper, with a low spending limit.
  • judgekeeper replaces anything that looks like a key with [REDACTED] in everything it prints or writes. That is a safety net, not a reason to paste keys anywhere.
